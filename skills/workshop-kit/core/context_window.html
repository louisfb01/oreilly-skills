And "context rot"?

Fitting in the window is not the same as being used well. In July 2025, Chroma tested 18 language models on deliberately simple tasks and changed only one thing: the amount of text in the input. They called the effect context rot: the fuller the window, the less reliable the model.

More text, less reliable

In every experiment, performance dropped as the input got longer, even though the task stayed the same.

In the simulator: paste a few documents and watch the meter drop.

Similar information confuses it

Sentences that look like the right answer but are wrong pulled performance down. One already hurt; several hurt more, and the effect grew with input length.

In the simulator: add "my sister's flight" a few times.

Vague questions suffer most

When the question and the answer do not share the same words, and the model has to infer the link, performance fell faster with long inputs.

In practice: ask directly and specifically.

The short version beats the full one

In a test with chat histories, models did much better with only the relevant part (about 300 tokens) than with the whole history (about 113,000 tokens).

In the simulator: compare "Summarise conversation" with letting everything pile up.

What this changes in your day-to-day

  • Changed topic? Open a new conversation instead of continuing the old one.
  • Paste only the part of the document that matters, not the whole file.
  • Avoid leaving old, contradictory versions of the same information in the chat.
  • In long chats, ask for a summary and continue in a new chat from it.

Source of the results: Hong, Troynikov and Huber, "Context Rot: How Increasing Input Tokens Impacts LLM Performance", Chroma, July 2025. The models tested were mid-2025 models; newer models can behave differently.

The simulator is a teaching simplification: token sizes are approximate, and each AI tool decides in its own way what to do when the window fills up.
